# PROMETEO EDGE STACK

Status: DESIGNING / NOT CURRENT
Owner candidate: `navigation.edge-stack`

## Purpose

Show that more destinations/content exist without spending meaningful viewport area on inactive navigation.

## Visual idea

The focused surface owns almost all useful space. Nearby destinations appear only as compact physical layers/tabs/edges, like sheets behind a document, but without forcing a literal folder-paper metaphor.

## Permanent constraints already accepted

1. Inactive destinations are **signals, not columns**.
2. Distant destinations may disappear completely outside the viewport.
3. The stack may show only the nearest few items even when there are 5, 50 or 500 destinations.
4. Desktop/horizontal layout: the compact stack lives primarily at the right/left edges.
5. Tablet/mobile/vertical layout: the same concept rotates to top/bottom, preserving native vertical scroll.
6. The active surface keeps roughly 85–95% of useful viewport area whenever content needs it.
7. Stack depth must never require thumbnails, bespoke artwork or per-destination CSS.
8. A node requires only universal navigation data; visual layers are generated by the shell.
9. The stack uses the shared Prometeo material owner rather than custom shadows.
10. Stack motion must be transform/opacity based where possible and must remain optional under reduced motion.
11. No counters, helper copy, breadcrumbs or chrome are added merely to explain that more items exist.
12. Native scrolling or direct tap remains the primary way to reveal additional destinations.

## What is intentionally NOT frozen yet

- exact tab width/height
- number of visible layers
- whether labels are always visible or only near focus
- exact depth offset
- whether edge layers are rounded rectangles, lines or partial surfaces

These remain visual-design decisions until a human-preferred specimen exists.
