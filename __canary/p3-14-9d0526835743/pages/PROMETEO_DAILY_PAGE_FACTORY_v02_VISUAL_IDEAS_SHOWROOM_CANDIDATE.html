principios

No diseñar widgets. Diseñar comportamiento.

Ideas tomadas del análisis de Life OS, adaptadas a Prometeo: menos carga mental, más loops cerrados, menos culpa, más retorno operativo.

Reducir carga cognitiva

La página no muestra todo. Primero muestra el foco, después lo secundario. La jerarquía protege la ejecución.

coreclaridad

Cerrar loops abiertos

Lo pendiente no se mezcla con lo urgente. Tiene una zona propia y puede pasar al return packet.

corememory

Ejecución según energía

No todos los días merecen el mismo sistema. Si la energía baja, la página reduce alcance.

candidatereset

Identidad operativa

No “cambiar tu vida”. Más simple: hoy soy estudiante, constructor, docente, integrador o recuperador.

candidatemodo

Feedback loops anidados

El cierre diario alimenta revisión semanal. No se pierde contexto entre chats o días.

corereturn

Sistema sin culpa

Si el día se rompe, no se reinicia el sistema. Se rescata un foco mínimo y se cierra con aprendizaje.

corehumano

capabilities

Qué se puede montar sin mezclar todo.

Daily Page no carga PageKit Interaction Core v37 por default. Solo monta capabilities si el pedido lo necesita.

Default: sin PageKit

La daily page normal usa shell + widgets. No carga presentation, toolbar ni whiteboard.

defaultliviano

Opcional: whiteboard

Si el usuario pide dibujar, se monta Whiteboard Core v37 como dependency locked.

optionallocked

Opcional: presentación

Si el usuario pide presentar el plan, se usa Presentation Shell v37 sin tocar toolbar ni markup.
