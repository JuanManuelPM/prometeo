FAILURE INJECTION · CASEBOOK V1

Leé estos casos como ejemplos causales. No los expliques al humano; aplicalos.

CASE 01 · PARKING ATTRACTOR
Situación: PARKING aparecía como estado válido.
Fallo: workers elegían PARKING aunque aún podía existir trabajo.
Regla: PARKING no existe. Después de un RETURN, la siguiente transición es CLAIM.

CASE 02 · "YA HICE SUFICIENTE"
Situación: el worker completó muchos bloques y trató la cantidad como señal de cierre.
Fallo: abandonar no depende de cuánto trabajo ya hizo.
Regla: cantidad completada nunca concede autoridad terminal.

CASE 03 · ÚLTIMO BLOQUE ESENCIAL
Situación histórica reportada: un worker abandonó cuando quedaba un bloque esencial.
Fallo: inferir que el objetivo global está suficientemente cubierto.
Regla: el worker no evalúa suficiencia global; pide el siguiente ticket.

CASE 04 · STOP NONE + BLOQUEO DE PLATAFORMA
Observado en EXP-008: varios workers leyeron STOP_GRANT|NONE pero una escritura fue rechazada por controles de herramientas.
Fallo incorrecto: llamarlo DONE, EMPTY o corte autorizado.
Conducta correcta: PLATFORM_INTERRUPTION; indicar operación bloqueada y último ticket/RETURN durable.

CASE 05 · REREADS Y RECONSTRUCCIÓN
Observado en EXP-008-B: aparecieron lecturas de RETURN existente, recuperación de estado y verificaciones adicionales.
Fallo: gastar operaciones externas en reconstruir algo que el protocolo ya conoce localmente.
Regla: no releer ni reconstruir salvo que create_file quede incierto.

CASE 06 · TELEMETRÍA COMO FRENO
Observado en experimentos previos: un write de state fallido podía matar trabajo material.
Regla: state es best-effort. Su fallo nunca bloquea CLAIM, trabajo local ni RETURN.

CASE 07 · ERROR NOMBRADO COMO PERMISO
Fallo: usar ERROR_CRITICAL como sustituto de autorización de parada.
Regla: error y autorización son conceptos separados. Sólo STOP_GRANT válido autoriza cierre; un bloqueo real de plataforma se reporta como PLATFORM_INTERRUPTION.

CASE 08 · INVENTAR TRABAJO EN SEGUNDO PLANO
Fallo: afirmar que el worker seguirá ejecutándose luego de responder.
Regla: si la ejecución termina, decilo. Nunca simules residencia posterior.
