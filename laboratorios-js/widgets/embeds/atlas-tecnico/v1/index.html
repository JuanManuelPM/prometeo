01 · Fuentes y tutoriales

Las transcripciones completas no se redistribuyen. Las explicaciones son reconstrucciones y análisis propios, con su orden técnico, errores, mejoras y variaciones.

F1 · TRANSCRIPCIÓN

Moddable SDK + Zephyr

Objetivo. JavaScript en hardware, NO iframes

Secuencia técnica y variaciones

[VIDEO] Kinoma y XS pequeño → XS-in-C / Zephyr → device tree y device.LED → temporizadores, GPIO, botones onReadable → REPL, breakpoints, memoria → bytecode en flash → fetch/JSON/Wi-Fi/Bluetooth → PIU.

[INFERENCIA] El diseño de adaptadores directos, contratos estandarizados ECMA-419, instrumentación y reducción de recursos inspira nuestro catálogo; el código no es transferible directamente al navegador.

[CORRECCIÓN] Motor Moddable no es un SDK de iframe; ninguna demostración ocurrió en Prometeo.

[EXTENSIÓN] Inspector de capacidades y rendimiento de herramientas externas

Peter Hoddie entrevistado por Benjamin · URL original no recibida

F2 · TRANSCRIPCIÓN

Últimos videos de YouTube con fetch

Objetivo. Tres videos recientes en iframes

Secuencia técnica y variaciones

[VIDEO] Crear HTML/CSS/JS → tres iframes vacíos → ID del canal → feed RSS → encodeURIComponent → servicio RSS→JSON → fetch() y response.json() → seleccionar items por posición → extraer video ID → construir /embed/ID → flexbox.

[INFERENCIA] Separar descubrimiento de contenido y reproductor permite canales dinámicos.

[CORRECCIÓN] Tres fetch repetidos, substring del ID frágil, medidas fijas, dependencia de conversor externo sin garantía de costo/CORS. No usa YouTube Data API directamente.

[EXTENSIÓN] Hemeroteca multicanal con normalización de enlaces y colecciones

Julia · URL original no recibida

F3 · TRANSCRIPCIÓN

PayPal: arquitectura de SDK client-side

Objetivo. Distribuir módulos de UI incrustables

Secuencia técnica y variaciones

[VIDEO] SDK inicial envolvía HTTP → pasó a componentes visuales → problema de NPM versionado y CDN evergreen → bundles bajo demanda con Webpack DefinePlugin y minimizador → import() asíncrono → configuración GraphQL preinsertada → fecha de versión → cache y rollback por dist-tags.

[INFERENCIA] Módulos desacoplados, compatibilidad, ruta crítica pequeña y posibilidad de reversión.

[CORRECCIÓN] No hace falta Webpack en servidor ni GraphQL para un laboratorio en GitHub Pages. Presenta estrategia histórica de PayPal, no receta universal.

[EXTENSIÓN] Adaptadores importados bajo demanda con validación de compatibilidad

Conferencista PayPal, identidad no constatable en texto · URL original no recibida

React Social Media Embed / Tweet / Share

Objetivo. Incrustaciones sociales, tienda y clon experimental

02 · Capacidades reutilizables

C1 · PATRÓN REUTILIZABLE

Detección de proveedores

Parsear URL HTTPS con URL(); exigir hostname allowlisted; normalizar rutas, IDs y parámetros; no aceptar coincidencias substring.

Limitaciones, errores y prueba

Riesgo: Esquema Provider {id,match,embed,capabilities,test}; evitar dominios impostores.

Aceptación: URL genuina se resuelve; dominio parecido se rechaza.

C2 · PATRÓN REUTILIZABLE

oEmbed

Consultar endpoints declarados de proveedor y obtener type/title/html; sanitizar estrictamente markup si fuera indispensable.

Limitaciones, errores y prueba

Riesgo: CORS, límites del proveedor, HTML remoto inseguro; en páginas estáticas puede requerir alternativa.

Aceptación: La fuente autorizada devuelve metadata o un estado de no disponible.

C3 · PATRÓN REUTILIZABLE

Iframes oficiales

Usar endpoint específico, title y permisos mínimos; dimensiones fluidas; preferir carga diferida.

Limitaciones, errores y prueba

Riesgo: load no significa que la app funcione; CSP, cookies y sandbox son restricciones.

Aceptación: Reproducir/manipular contenido en navegador real.

C4 · PATRÓN REUTILIZABLE

API de GeoGebra

Cargar deployggb.js, crear GGBApplet y recibir appletOnLoad; evalCommand y API de estado/eventos.

Limitaciones, errores y prueba

Riesgo: El iframe host sin allow-same-origin puede requerir diseño alternativo: no declarar probado.

Aceptación: Crear f(x), leer objeto, restaurar material o exportar.

C5 · PATRÓN REUTILIZABLE

Editor diagrams.net

https://embed.diagrams.net/?embed=1&proto=json y protocolo postMessage init/load/save, XML import/export.

Limitaciones, errores y prueba

Riesgo: Filtrar event.origin y event.source, correlacionar respuestas, validar JSON/XML.

Aceptación: Enviar documento, editar, salvar y verificar XML producido.

C6 · PATRÓN REUTILIZABLE

Reproductor YouTube

IFrame Player API oficial con onReady, onStateChange, loadVideoById.

Limitaciones, errores y prueba

Riesgo: Autoplay restringido; video puede deshabilitar embeds.

Aceptación: Controles Play/Pause y eventos de estado en video embebible.

C7 · PATRÓN REUTILIZABLE

Descubrimiento RSS

Una solicitud por canal, ordenar/deduplicar resultados y construir representación segura.

Limitaciones, errores y prueba

Riesgo: Feed XML de YouTube no garantiza acceso navegador por CORS; no asumir proxy ilimitado.

Aceptación: Comparar con fixture y simular falla de feed sin resultados falsos.

C8 · PATRÓN REUTILIZABLE

Componentes React

react-social-media-embed para múltiples posts; react-tweet especializado; react-share para acciones.

Limitaciones, errores y prueba

Riesgo: Dependencia React pesa; CDN y CSP pueden fallar; preview no equivale a interacción.

Aceptación: En cada red verificar el gesto principal permitido y su fallback.

C9 · PATRÓN REUTILIZABLE

Carga selectiva

Separar adapters por import() y no cargar SDK externos antes de necesitarlos.

Limitaciones, errores y prueba

Riesgo: Evitar dependencias rotas o evergreen impredecibles.

Aceptación: Inspeccionar red y confirmar que proveedor inactivo no descarga código.

C10 · PATRÓN REUTILIZABLE

Mensajes cross-origin

postMessage(data,targetOrigin) y listener que valida origin/source/tipo/id.

Limitaciones, errores y prueba

Riesgo: Mensajes no confiables; jamás usar '*' salvo caso documentado.

Aceptación: Mensaje de origen falso se descarta; válido produce transición.

C11 · PATRÓN REUTILIZABLE

Estados honestos

State machine: detectado, conectando, listo según API, interacción verificada, bloqueado, externo.

Limitaciones, errores y prueba

Riesgo: No marcar éxito a partir de onload, timeout silencioso o captura.

Aceptación: Fallos se muestran con causa, salida externa y reintento real.

C12 · PATRÓN REUTILIZABLE

Preservación de ventanas

Separar geometría, z-index, herramienta e información que su SDK deja serializar; restaurar mediante importación explícita.

Limitaciones, errores y prueba

Riesgo: Sandbox de Laboratorios no admite localStorage fiable. Sesiones de terceros no necesariamente recuperables.

Aceptación: Exportar JSON, recargar y restaurar posición/objeto cuando es posible.

C13 · PATRÓN REUTILIZABLE

Compartir contenido

Web Share API con fallback a copiar URL canónica; botones específicos opcionales.

Limitaciones, errores y prueba

Riesgo: No compartir localhost ni rutas inexistentes.

Aceptación: Compartir y abrir la URL desde una sesión diferente.

C14 · PATRÓN REUTILIZABLE

Accesibilidad y móvil

viewport fluido, controles de 44px, etiquetas, teclado, foco, scroll vertical completo.

Limitaciones, errores y prueba

Riesgo: Captura de rueda/gestos por iframe puede impedir scroll.

Aceptación: Comprobar 360px, tabulación y escalado sin recorte.

C15 · PATRÓN REUTILIZABLE

Privacidad y licencias

Permisos mínimos por iframe; explicar solicitudes a terceros; licencias verificadas; sin secretos cliente.

Limitaciones, errores y prueba

Riesgo: Las librerías open source y servicios externos tienen condiciones diferenciadas.

Aceptación: Ningún token o material privado aparece en HTML ni telemetría.

04 · Tres experiencias planificadas

La orden futura «.» habilita desarrollo, pruebas y publicación; hoy solo se registran objetivos verificables.

1 · Emblemática · NO CONSTRUIDA

Mesa Viva

Escritorio académico de tres ventanas auténticas: GeoGebra, diagrams.net y cuaderno Markdown.

Arquitectura, interacción, pruebas y alcance

Flujo: Abrir/reorganizar ventanas → crear gráfica vía API de GeoGebra → dibujar en diagrams.net → aplicar cambios y exportar XML → editar nota → exportar un paquete portable → importar y recuperar estado permitido.

Diseño: Mesa editorial oscura, tipografía sobria, jerarquía clara, foco visible y ventanas verdaderamente móviles en pantalla ancha; scroll natural en celular.

Componentes: window shell independiente; adaptadores GeoGebra/diagrams.net; editor Markdown accesible; export JSON/XML; event bus tipado.

Dependencias: GeoGebra y diagrams.net oficiales por red, editor propio sin bibliotecas pesadas; revisar términos antes de publicar.

  • Si appletOnLoad no llega, aparece bloqueo verificable y enlace oficial.
  • Si diagrams.net envía init/load/save válidos, XML se exporta; un origen falso se ignora.
  • Importar JSON recupera geometría y documento local; nunca promete sesión remota.
  • 360px, teclado, scroll, iframe sandbox y permisos revisados.

Aceptación: Acciones genuinas sobre ambas herramientas externas; nada de botones «mostrar» ficticios.

Ampliación: Integrar lectores académicos y transferencia de datos consentida.

2 · Laboratorio interactivo · NO CONSTRUIDA

Inspector de Integraciones

Mesa de pruebas de URLs y SDK que registra evidencia de capacidad, fallos y protocolos.

Arquitectura, interacción, pruebas y alcance

Flujo: Elegir URL permitida → seleccionar adaptador → habilitar carga → ver handshake y capacidades → probar acción → obtener estado y exportar informe.

Diseño: Herramienta técnica legible como una consola profesional, no dashboard estadístico falso.

Componentes: allowlist y URL normalizer; adapter registry; state machine; mensajes seguros; tests por proveedor; export JSON.

Dependencias: JavaScript estándar, SDK oficiales opcionales.

  • Dominio impostor bloqueado.
  • iframe load aislado no se considera verificación de interacción.
  • Timeout conserva causa y ofrece apertura externa.
  • Mensajes de window u origin ajeno descartados.
  • La descarga contiene eventos reales sin credenciales.

Aceptación: Proporciona evidencia reproducible o comunica bloqueo sin fingir funcionamiento.

Ampliación: Agregar pruebas de regresión de proveedores.

3 · Variación radical · NO CONSTRUIDA

Hemeroteca Viva

Transformar «los tres últimos videos» de Julia en una biblioteca multimedia investigable y exportable de fuentes de distintas redes.

Arquitectura, interacción, pruebas y alcance

Flujo: Pegar URL → detectar proveedor → elegir embed/SDK/enlace externo → anotar, categorizar y fijar → reproducir videos compatibles → exportar/importar colección → consultar novedades solo si feed realmente disponible.

Diseño: Revista visual de referencias con visor ancho, sin tarjetas genéricas ni ornamentalismo.

Componentes: provider resolver; adapters YouTube/redes; modelo de colecciones; filtro/búsqueda; export JSON; visor de media.

Dependencias: YouTube iframe API y SDK de posts según compatibilidad; RSS opcional y sin proxy de pago.

  • URLs inválidas y duplicadas tratadas.
  • YouTube reproducible y contenido social con fallback honesto.
  • Colección se conserva export/import y búsqueda funciona.
  • Sin feed accesible no se simulan actualizaciones automáticas.
  • Responsive 360px y navegación teclado.

Aceptación: Dos clases distintas de recursos funcionen realmente; export-import y búsqueda operativos.

Ampliación: oEmbed ampliado e indexación consentida.

05 · Decisiones y límites

  • Mantener intactos los escritorios V19-V22 existentes
  • Distinguir embed oficial, componente instalable y enlace externo
  • No prometer integración de WhatsApp, Gemini o ChatGPT sin prueba en navegador
  • No depender de localStorage en iframe sandbox
  • No importar la infraestructura servidor de PayPal al laboratorio estático
  • No inventar títulos/links originales de videos
  • No publicar tres demos hasta que llegue el punto

[INVESTIGACIÓN] Las páginas oficiales enlazadas documentan APIs existentes, pero la compatibilidad concreta con las restricciones del iframe de Prometeo todavía necesita validación de navegador. No se usaron datos personales, archivos académicos ni credenciales.
