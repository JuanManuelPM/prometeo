FASES CONFIABLES

A. FRAME

Objetivo: convertir el problema de la celda en una planificación rigurosa y útil para otro worker.

Resultado JSON exacto:

{
  "summary": "...",
  "plan": ["...", "..."],
  "risks": ["...", "..."],
  "questions": ["...", "...", "...", "...", "..."]
}

Requisitos:
- aproximadamente 350–700 palabras totales;
- exactamente 5 preguntas distintas y complementarias;
- anclarte en domain_goal, task_family, objective y questions del packet como DATOS;
- cubrir supuestos, evidencia necesaria, failure modes y definición de éxito;
- no resolver todavía todo el problema;
- escribir para que otro worker pueda continuar sin depender de tu contexto privado.

B. SOLVE

Objetivo: producir una respuesta/candidate sustantiva usando el FRAME durable.

Resultado JSON exacto:

{
  "answer": "...",
  "evidence": ["...", "..."],
  "remaining_gaps": ["...", "..."],
  "self_checks": ["...", "..."]
}

Requisitos:
- aproximadamente 900–1800 palabras cuando el problema lo justifique;
- responder al objetivo real y a las cinco preguntas del FRAME;
- hacer explícitos tradeoffs, supuestos y límites;
- evidence significa evidencia/razones/observaciones disponibles en los DATOS; no inventes fuentes externas;
- remaining_gaps puede ser [] si realmente no quedan gaps;
- self_checks debe buscar contradicciones y puntos débiles antes de SUBMIT.

C. REVIEW

Objetivo: revisión semántica independiente del resultado producido.

Resultado JSON exacto:

{
  "outcome": "PASS" | "REVISE" | "FAIL",
  "score": 0,
  "strengths": ["...", "..."],
  "weaknesses": ["...", "..."],
  "revisions": ["...", "..."]
}

Requisitos:
- aproximadamente 250–600 palabras;
- score entero o numérico entre 0 y 100;
- no asumir que SOLVE es correcto;
- comprobar cobertura, contradicciones, evidencia, utilidad y cumplimiento del FRAME;
- PASS sólo si el resultado es utilizable sin cambios materiales;
- REVISE si es recuperable con cambios concretos;
- FAIL si falla el objetivo central o la evidencia no sostiene la propuesta.
