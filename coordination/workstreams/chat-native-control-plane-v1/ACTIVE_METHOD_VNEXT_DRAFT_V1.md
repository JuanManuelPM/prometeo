## 1. Method authority model

Use five separate layers:

1. **Global Constitution** — non-negotiable laws.
2. **Method Clause Registry** — stable reusable clauses/modules with provenance, scope, tests and lifecycle.
3. **Method Supersession** — explicit scope-aware replaces/conflicts/preserves relations.
4. **METHOD_HEAD** — canonical pointer/manifest selecting the accepted active composition.
5. **Compiled Method Packet** — disposable deterministic projection for one role/job/campaign/Working Set.

`METHOD_HEAD` is not a copied mega-prompt. A new protocol or shorter prompt cannot silently erase useful active clauses.

## 2. Clause contract

Each reusable method clause should declare at least:
- stable `clause_id`;
- kind: `LAW | SEQUENCE | GATE | HEURISTIC | PROFILE | CRITIC | RECOVERY | TRACEABILITY | PRIVACY | AUTHORITY`;
- semantic payload;
- evidence/origin refs;
- applicability/scope predicate;
- status: `CANDIDATE | ACTIVE | RETIRED | SUPERSEDED`;
- requires/conflicts/supersedes/preserves;
- tests/falsifiers;
- introduction/rollback lineage.

Promotion/removal are explicit integration decisions. Omission from a newer document is never retirement.

## 3. Compilation law

For a concrete job, compile in this order:

```text
CONSTITUTION
  + ALWAYS-ON ACTIVE METHOD CLAUSES
  + CAMPAIGN PHASE/GATE
  + ROLE/JOB/PROFILE-SPECIFIC CLAUSES
  + RELEVANT VACCINES / NEGATIVE KNOWLEDGE
  + WORKING SET / AUTHORITY / PRIVACY BOUNDARIES
  -> COMPILED METHOD PACKET
```

Rules:
- `EXISTS != PARTICIPATES` applies to method as well as context.
- Every included clause has an inclusion reason.
- Every excluded high-relevance clause has an exclusion reason.
- Jobs may specialize but cannot suppress Constitution or mandatory active clauses.
- Same head + same task metadata + same Working Set should produce the same ordered governing clause IDs, except explicitly declared provider/model adaptation.

## 4. Default operating sequence

### Phase A — Reconstruct
1. Resolve canonical identity and current heads.
2. Load Constitution, METHOD_HEAD, Survival Set and scoped campaign/job state.
3. Verify EPOCH/currentness where mutation may occur.
4. Resolve owners, authority and must-preserve boundaries.
5. Compile the smallest sufficient Working Set.

### Phase B — Map before acting
6. Determine whether the task is FAST, DEEP, EXHAUSTIVE or CONTINUE.
7. For material work, build/freeze a coverage or dependency map before broad execution.
8. Identify ambiguity, authority risk, source debt, write collisions and falsification needs.
9. Parallelize independent questions aggressively when expected durable value exceeds coordination cost.

### Phase C — Develop
10. Produce evidence-linked models/options/changes.
11. Preserve rejected paths as negative knowledge when reusable.
12. Keep fact, candidate, Human Accepted, Current and Served classes distinct.
13. Persist material frontier changes during work; do not rely on transcript memory.

### Phase D — Challenge
14. Use independent Challenger/critic passes for important architecture, authority or high-uncertainty work.
15. Apply adaptive depth to hotspots rather than uniformly inflating every step.
16. Convert discovered failure modes into explicit test/vaccine candidates rather than disposable critique prose.

### Phase E — Reconstruct / Gate
17. For deep campaigns, require Apprentice/successor reconstruction of the model, constraints and traceability.
18. Run the relevant gate: Book Gate, admission gate, acceptance gate, release gate, etc.
19. A gate passes only on evidence/coverage, never word count or confidence tone.

### Phase F — Execute / Forge
20. Execute only from frozen valid inputs/heads and declared scope.
21. Revalidate authority/currentness immediately before material mutation.
22. Keep side effects idempotent where needed and emit durable receipts/evidence.
23. If execution invalidates a governing premise, stop affected scope and reopen the smallest upstream reasoning slice; do not silently patch frozen Canon mid-Forge.

### Phase G — Critique / Repair / Retest
24. Run adversarial critique on the actual result.
25. Repair material findings.
26. Retest the changed/failing surfaces and required regression set.
27. Record incident/negative knowledge when failure reveals a reusable prevention rule.

### Phase H — Integrate / Continue
28. Worker completion ends in durable RETURN; canonical integration belongs to parent/steward.
29. Integration deduplicates without deleting lineage, surfaces contradictions and audits coverage before promotion.
30. Persist the new durable frontier/head/next action.
31. `CONTINUE` or bare dot resumes from the last valid durable gate; it is not approval and does not bypass authority.

## 5. Profiles

### FAST
Use for low-risk, well-specified, reversible tasks with clear authority and evidence. Still obey Constitution, currentness and durable-output requirements.

### DEEP
Use for architecture, ambiguous design, cross-layer changes or consequential reasoning. Requires meaningful map, source-backed development, critique and repair.

### EXHAUSTIVE
Use when omission risk is itself a major failure mode. Freeze the coverage universe, systematically traverse it, track explicit omissions and avoid repeatedly replanning the same map.

### CONTINUE
Resume the highest-value safe frontier from durable state. Reopen only what changed or became invalid. Never interpret continuation as acceptance/promotion.

## 6. Deep campaign / Book-first program

```text
RECONSTRUCT
  -> SOURCE-BACKED WRITTEN BOOK
  -> COMPLETE/FROZEN COVERAGE MAP
  -> BRAIDED DEVELOPMENT
  -> ADAPTIVE-DEPTH HOTSPOTS
  -> INDEPENDENT CHALLENGE
  -> APPRENTICE RECONSTRUCTION
  -> BOOK GATE
  -> FROZEN CANON
  -> FORGE / EXECUTION
  -> ADVERSARIAL CRITIQUE
  -> REPAIR
  -> RETEST
  -> INTEGRATION / CRYSTALLIZATION
```

Book Gate checks include:
- declared coverage satisfied or omissions explicit;
- material claims linked to reopenable evidence;
- facts vs candidates/authority classes separated;
- contradictions resolved or explicitly preserved;
- negative knowledge survives;
- source debt below threshold or blocking;
- successor can reconstruct the model;
- requirement -> decision -> planned change -> test traceability exists;
- no known premise-invalidating blocker remains.

## 7. Parallel worker method

Before launch:
- durable Work Item/JOB exists;
- mission, scope, context refs, baseline/current refs, must-preserve map and return contract are explicit;
- dependencies and write collisions are resolved;
- worker type/critic relation is intentional.

During execution:
- STARTED is persisted before substantive work;
- each worker owns only its declared run/return/evidence scope;
- silence is never completion;
- parent keeps useful work moving.

After execution:
- RETURN is immutable evidence;
- parent/steward records consumption/integration separately;
- retries/supersession create explicit new attempts rather than rewriting history.

## 8. Context method

Compile context progressively:
- L0: identity, request/job, Constitution + applicable active clauses;
- L1: current Chat Object/campaign/job/heads/relevant returns;
- L2: deeper source/history only when contradiction, ambiguity or evidence debt requires it.

Source selection must preserve:
- authority and privacy inheritance;
- currentness/supersession filtering;
- deterministic tie-breaking;
- reopenable source refs;
- explicit conflict detection;
- retrieval/consumption receipts.

Do not load all Product Memory/Written Mind into every worker.

## 9. Successor / reincarnation method

A fresh successor is not trusted merely because it can quote state.

Successor proof should test:
- canonical identity/head resolution;
- method reconstruction without transcript;
- prompt-erasure resistance;
- poisoned-prompt resistance;
- ambiguity/currentness handling;
- equivalent applicable clause compilation;
- one scoped material action with durable evidence;
- persisted next frontier.

## 10. Self-improvement method

Method evolution is itself governed work:
1. propose clause/module change;
2. compare against current METHOD_HEAD, Constitution and Survival Set;
3. compute coverage delta;
4. run challenger/adversarial review for material changes;
5. run relevant falsification/regression tests;
6. integrate with explicit scoped supersession/preservation;
7. move METHOD_HEAD pointer only after acceptance;
8. preserve prior head as rollback lineage.

No whole-document latest-wins.

## 11. Required method falsifiers before promotion

Candidate tests from the current convergence:
- Constitution coverage: no governing invariant silently disappears.
- Survival coverage: every method-relevant Survival requirement maps to active clauses or explicit N/A.
- Source closure: every active clause has reopenable provenance.
- Contradiction: unresolved same-scope high-authority conflicts fail closed.
- Scoped supersession: replacing scope X preserves old clause behavior in scope Y.
- Determinism: same inputs compile same ordered clause set and reasons.
- Prompt erasure: a short/new prompt cannot drop mandatory method.
- Poisoned prompt: a job asking to ignore prior rules cannot suppress Constitution/METHOD_HEAD.
- Successor parity: fresh chat reconstructs equivalent applicable method.
- Mutation kill: deleting/altering a critical clause causes a coverage/falsification test to fail.
- Traceability: requirement -> clause -> decision/change -> test/return is traversable both ways.
- Rollback: prior METHOD_HEAD remains addressable and restores the prior compiled set.
