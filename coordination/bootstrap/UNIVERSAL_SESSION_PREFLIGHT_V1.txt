PROMETEO · UNIVERSAL SESSION PREFLIGHT V1
Status: BINDING CONTINUITY GUARD
Purpose: every fresh interactive chat/Guide/session and every material worker mutation must understand where it is in Prometeo before changing durable state.

THIS DOES NOT CREATE A NEW AUTHORITY.
Current Tree, Organism, Work Context, source owners, Design DNA and the worker packet keep their existing roles.

============================================================
A · INTERACTIVE CHAT / GUIDE · BEFORE MATERIAL MUTATION
============================================================

Mandatory orientation order:

1. CURRENT TREE V2
   Read the current continuity index first.
   Stable human entry:
   https://juanmanuelpm.github.io/prometeo/current-tree/

2. CURRENT ARCHITECTURE
   Resolve which architecture is CURRENT and which candidates/legacy paths must not be resurrected.

3. ORGANISM
   Read the Living Organism/current projection and locate the target object, its owner, parents, dependencies and related surfaces.
   Do not merely note that the organism exists: identify where your target sits and what can regress if it changes.

4. OBJECTIVE / PLAN / CURRENT STATE
   Read the target project's current objective, plan/checkpoint, active constraints, latest durable decisions and exact next action.
   Prefer durable source owners over chat recollection.

5. WORK CONTEXT / SESSION LINEAGE
   Reopen the relevant Work Context and, if this is a reincarnated chat, predecessor SESSION/JOURNAL.
   Exact prompts remain private by default. Public journal is continuity projection, not authority.

6. DESIGN DNA / GOLDEN / PRESERVATION
   If the requested work can materially alter architecture, orchestration, persistence, recovery, global UI behavior, worker ABI, Guide coordination or a known-good product flow:
   read coordination/design-dna/INDEX.json and the required stack.
   Identify touched invariants, failure vaccines and last-known-good baseline before editing.

7. DRIFT
   Compare:
   requested human delta
   vs current plan/objective
   vs current bytes/runtime evidence
   vs known baseline.
   State internally what changed since the last checkpoint.

Only then mutate durable state.

============================================================
B · CLASSIFY THE HUMAN REQUEST
============================================================

Every material human request must be treated as one of:

CONTINUE
- advances the current plan without changing its contract.

COMPATIBLE_DELTA
- adds or improves something while preserving current objective/baseline.

EXPERIMENT
- explores a different option without replacing CURRENT.
- isolate it as candidate/alternative and retain comparison evidence.

REPLAN
- intentionally changes objective/order/strategy.
- record what plan is being superseded, why, what is preserved, and exact rollback/history refs.

DESTRUCTIVE_RESET
- explicitly asks to remove/rebuild/replace known-good behavior.
- obey the human directive, but do not silently erase history.
- preserve a rollbackable baseline/reference whenever technically possible unless the human explicitly requires irreversible destruction.
- record the destructive intent, previous plan, affected invariants and new target.

A new request is NOT permission to forget the previous plan.

If the human says something apparently contradictory or likely to move the project backward:
- do not ignore the human;
- explain/represent the conflict in the durable decision;
- prefer an isolated experiment/alternative when that satisfies the request;
- if the human clearly requests the replacement anyway, execute it within authority while preserving lineage/evidence.

============================================================
C · WORKER RULE
============================================================

A worker must NOT use this preflight to choose project, task, priority, family or queue.

Worker order:
1. obtain fresh worker identity / dispatch through the CURRENT worker entrypoint required by its worker prompt;
2. if dispatch returns WORK, obey packet scope/tool_policy/authority;
3. BEFORE any material GitHub/runtime mutation:
   - read this preflight;
   - inspect Current Tree status relevant to the target;
   - locate the target in Organism / source-owner context when available;
   - read Design DNA only when the packet touches material architecture/global behavior;
   - preserve the packet's allowed_paths/done_when as the hard mutation boundary;
4. execute only the packet;
5. return evidence/results through the existing worker protocol.

Organism/context informs execution. It never expands worker authority.

============================================================
D · FRESH CHAT SESSION / REINCARNATION
============================================================

Every adopted fresh chat:
1. creates a NEW session_id + session_pin;
2. links predecessor_session_id when continuing;
3. reads this preflight;
4. reads Current Tree + relevant Organism/objective/plan + predecessor journal/source owners;
5. publishes SESSION.json/JOURNAL.json/CONTINUE.txt before substantial long-lived work when the durable path is available;
6. journals every material turn before final reply:
   human intent summary, conclusion, real actions, refs, decisions, boundaries, next action;
7. never publishes raw private prompts, note bodies, tokens, Authorization headers or hidden chain-of-thought.

============================================================
E · DEFINITION OF CONTINUITY SUCCESS
============================================================

A fresh shell should be able to answer, from durable state:

- WHAT is the human trying to achieve?
- WHERE does this object live in the organism?
- WHAT is CURRENT vs CANDIDATE/LEGACY?
- WHAT plan was active?
- WHY was that plan chosen?
- WHAT known-good behavior must survive?
- WHAT changed recently?
- WHAT did the human request now?
- IS it continuation, compatible delta, experiment, replan or destructive reset?
- WHAT exact next action is safe and authorized?
- WHERE will the result/journal/evidence be written?

If any of those answers are materially unknown, inspect the existing owners before redesigning.

CORE LAW:
HUMAN DIRECTIVE IS THE NEW INTENT.
DURABLE HISTORY IS THE CONTEXT.
NEW INTENT MAY CHANGE THE PLAN.
NEW INTENT MUST NOT SILENTLY ERASE THE REASONING, BASELINE OR LINEAGE THAT CAME BEFORE IT.
