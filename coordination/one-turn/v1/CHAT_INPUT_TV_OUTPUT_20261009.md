# Entrada por chat · salida GitHub Pages en tele · V1
Fecha: 2026-10-09. El usuario simplificó conscientemente el plan: **NO hace falta input en la web**, puede abrir un chat NUEVO y escribir UNA sola tarea humana en ChatGPT. ChatGPT usa sus herramientas conectadas a GitHub/Calendar/Drive, si están efectivamente disponibles, para modificar el dueño correcto y verificar. La **pantalla GitHub Pages queda abierta en la tele** y consulta cada 15 segundos `tv/chat/state.json`, una proyección pública de resultados reales. No es un worker, no es persistencia privada, no corre código cuando termina el chat. No se promete sincronización instantánea por CDN.
URL visual: https://juanmanuelpm.github.io/prometeo/tv/chat/
Owner TV: gh-pages:tv/chat/index.html, state.json, README.md. No tocar tv/ai/index.html (telemetría anterior con Supabase). El visor embebe la página del widget existente y muestra últimos resultados no privados. El control en ChatGPT puede seleccionar `focus.path` para apuntar al calendario, estudio o widget sin diseñar otra página.
FIRE: `🔥prometeo <tarea>` = elegir skills y ACTUAR en 1 mensaje. `🔥prometeo` solo = inspección y plan. `🔥preparar <tarea>` + `.` = modo deliberado optativo.
No se integró skill de GitHub al Proyecto automáticamente; instrucciones de GitHub solamente funcionan si el chat las consulta. Para un chat nuevo totalmente aislado hace falta bootstrap de Proyecto o instrucción inicial que apunte a esos owners. La propuesta NO asegura que cada chat lea por defecto repos remotos.
No publicar datos privados: calendarios personales y tareas privadas en Google Calendar/Drive autorizados o local. GitHub Pages es público. No introducir Supabase, workers ni despliegues pagos como requisito de la tarea del chat. Preservar trabajos PR70/PR71, widget API y V15; no rediseñar hasta recibir fotos de referencia.
