# 10 · WHY STORAGE FILLED / FAILURE VACCINE

Known architectural failure:

a HOT database intended for private/transient state accumulated too much operational exhaust:

- heartbeat/session/progress style events;
- write-on-read / last_seen classes;
- repeated polling/progress telemetry;
- captures/revisions/pages/workspace updates;
- large schema/runtime surface;
- insufficient bounded retention / write budget.

Exact byte attribution remains UNKNOWN while Postgres cannot be safely measured.

Vaccine:

Every new runtime feature must declare:

- writes per human action;
- writes per WC productive unit;
- writes per idle minute;
- estimated bytes/day;
- retention/compaction owner;
- failure blast radius.

Hard gates:

- **NO WRITE ON READ**
- **NO UNBOUNDED HOT STORAGE**
- **NO SILENT RETRY STORM**
- **NO SINGLE HOT SERVICE AS DURABLE MEMORY**

These must become executable tests/ratchets, not prose only.
